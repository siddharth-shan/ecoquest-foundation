# Event listing images

Cover images for the seminar listings, plus the October campaign flyer.
Eventbrite wants **2160 × 1080** (2:1); every cover here is exactly that.

| File | Use it for |
|------|------------|
| `wildfire-banner.png` | Sep 12 — Reading Real Wildfire Data |
| `beach-cleanup-banner.png` | Sep 26 — What a Beach Cleanup Actually Tells Us |
| `home-footprint-banner.png` | Oct 10 — Your Home's Water and Energy Footprint |
| `climate-anxiety-banner.png` | Oct 24 — Climate Anxiety and How We Built MindMirror |
| `local-conservation-banner.png` | Nov 7 — Conservation in Your Own Neighborhood |
| `ecoquest-series-banner.png` | Organizer profile header, and any session without its own |
| `logo.png` | Organizer profile picture (1024 × 1024, square) |

Sessions 2–5 are generated by `gen-session-banners.py`; edit that file and re-run
it rather than editing the four HTML files, which it overwrites.

## The October campaign flyer

| File | Size | Use it for |
|------|------|------------|
| `october-campaign-poster.png` | 1200 × 1700 | Printed flyer; also published to the site |
| `october-campaign-banner.png` | 2160 × 1080 | Eventbrite cover and social posts |

Both are generated by `gen-campaign-poster.py`, which **reads the facts straight
out of `src/data/campaigns.ts`** rather than having them retyped. That is the
whole point: a poster that quotes the data file cannot quietly disagree with the
website. It also writes `public/images/campaigns/october-2026-poster.{png,webp}`,
so re-running the script is all it takes to update the flyer shown on `/events/`.

```bash
python3 -m venv .venv && .venv/bin/pip install segno pillow
.venv/bin/python docs/eventbrite/gen-campaign-poster.py   # from the repo root
```

The QR codes are generated offline from the `registrationUrl` of each campaign,
so the printed poster and the site's buttons always point at the same place.
**After re-rendering, decode them before shipping** — a QR code that silently
encodes the wrong URL looks identical to one that does not.

## What goes on a banner, and what does not

No photographs of people. The event photos in `public/images/events/` are not
used here: some are Scout-attributed, and none are needed.

`public/images/mission.png` is an AI-generated illustration of students who do
not exist. It is fine as decorative art on the website, but it must not go on an
event listing, where it reads as a photo of a real EcoQuest session.

**`public/images/apps/oceanaware.png` was re-captured for this reason.** The old
screenshot showed a "Contest Entry — Bow Seat 2026" card. EcoQuest never entered
Bow Seat. Commit 573d3a7 removed the claim from the site's text and the app
itself was fixed separately, but the stale screenshot kept republishing it as a
picture on four pages long after the words were gone.

The lesson generalises: **a retraction is not finished until the images are
re-captured too.** Text greps clean while a claim survives in a PNG. When a
claim is pulled, re-shoot every screenshot that showed it.

An app screenshot is only paired with a session when the app genuinely relates to
it, and the caption states what the app is — never what the session will cover.

The MindMirror crop on the Oct 24 banner is deliberately cut above the feature
cards. The full screenshot advertises "70%+ accuracy" and "First tool to
specifically detect lack of joy — a key depression indicator." Those are clinical
claims, and a public event listing is not the place to repeat them.

`beach_cleanup1.jpeg` is captioned "one of our own beach cleanups" with no date or
location, because the site's own caption for that file gives neither. The Seal
Beach / Save Our Beach attribution belongs to a different photo.

Everything on the banners is true as of the day they were made: the dates match
`src/data/seminars.ts`, and the app screenshot is the real Wildfire Watch UI, not
a mockup. If the schedule changes, re-render — do not ship a banner that
disagrees with the site.

## Re-rendering

The banners are HTML rendered to PNG with headless Chrome. Edit the `.html`
file, then from this directory:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=2160,1080 --allow-file-access-from-files \
  --screenshot="ecoquest-series-banner.png" "file://$PWD/ecoquest-series-banner.html"
```

`logo.png`, `wildfire-watch.png`, `greenledger.png`, `mindmirror.png`, and
`beach_cleanup1.jpeg` are copies of the originals in `public/`,
kept here so the HTML resolves its images relatively and the render is
reproducible from this folder alone.
