# This Week for the Planet v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand the homepage "This Week for the Planet" section to 31 observances (including rule-dated days), a "why it matters" line per day, a monthly Southern California season card, countdowns and "Add to calendar", and keep it current with zero manual work (weekly rebuild + weekly link check).

**Architecture:** Data lives in `src/data/awarenessDays.ts` (days with fixed-date or nth-weekday rules) and `src/data/seasons.ts` (12 monthly entries). Pure functions in `src/lib/planetCalendar.ts` turn a date into everything the section shows (`occurrence`, `nextAwarenessDays`, `weeklyPick`, `seasonFor`, `countdown`, `icsFor`). The client component renders with the build date then swaps in the visitor's date. A GitHub Actions workflow rebuilds the static site weekly via a Vercel Deploy Hook and runs a link checker that opens a GitHub issue on breakage.

**Tech Stack:** Next.js 14 App Router (static export), React 18, TypeScript, Tailwind 3, vitest 3.2.4, Node 24, GitHub Actions, `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-27-this-week-v2-design.md` (evidence: `docs/superpowers/specs/2026-10-27-this-week-v2-sources.md`)

## Global Constraints

- Every `why` line and season entry is copied **verbatim** from this plan (which copies spec Appendix A/B). Do not reword.
- No year appears in any `why` or season `text`/`heading` (historical years like 1973 and 1987 are allowed; nothing 2020–2099).
- Observance link text is the day's `source` label ("UN observance", "FAO", "WMO", "UNEP", "Arbor Day Foundation", "World Migratory Bird Day", "California Coastal Commission", "World Rivers Day"). The EcoQuest pairing is shown only as "Try: …".
- US spelling. K-12-appropriate copy.
- Tests run with `npm test` (`TZ=America/Los_Angeles vitest run`).
- Day URLs must be `https://`; season source URLs may be `http://` or `https://` (LA County Public Health's beach page is http-only — spec Appendix A note).
- No new runtime dependencies.
- Nothing is pushed to `main` or deployed until the user has reviewed the local build.

## Review Focus

1. **A rule day on its own date** (e.g. Sep 19, 2026 is Coastal Cleanup Day) must show `daysAway` 0 and "Today", not jump to next year. → Task 1 test "counts a rule day on its own date as today".
2. **Season card late on the last evening of a month** must still show that month. → Task 2 test "uses the visitor's local month late at night".
3. **Long calendar lines** (DESCRIPTION is often > 75 chars) must be folded per RFC 5545 or some calendar apps reject the file. → Task 3 test "folds lines longer than 75 characters".
4. **A non-ASCII character in copy** would make character-based folding exceed 75 octets. → Task 1 data test "copy is plain ASCII".
5. **Sites that refuse HEAD** (405/403) must not be reported broken if GET works. → Task 5 test "falls back to GET when HEAD is refused".

## Rulings made while planning

- Spec §3 says season sources are https; Appendix B (later, more specific) uses an http source for January. Appendix B wins: season URL test is `^https?://`; day URLs stay `^https://` (all are https).
- RFC 5545 requires `DTSTAMP` in a VEVENT and line folding; the spec omits both. `icsFor` adds them, with `now` as an optional parameter so tests are deterministic.
- The rotation "stable within a week" / "cycles" tests previously relied on Jul–Aug having no observances; Jul 12 and Aug 27 are now observances, so those two tests pass `[]` as the days list to test rotation alone.
- GitHub disables scheduled workflows in public repos after 60 days with no repository activity. The workflow re-enables itself each run through the Actions API (the technique used by `liskin/gh-workflow-keepalive`), which resets that timer — required by "no manual intervention".

```ts
/** Local midnight of a rule's date in a given year. */
export function occurrence(rule: DateRule, year: number): Date {
  if ('day' in rule) return new Date(year, rule.month - 1, rule.day)
  if (rule.nth === 'last') {
    const last = new Date(year, rule.month, 0) // day 0 of next month = last day of this one
    return new Date(year, rule.month - 1, last.getDate() - ((last.getDay() - rule.weekday + 7) % 7))
  }
  const first = new Date(year, rule.month - 1, 1)
  return new Date(year, rule.month - 1, 1 + ((rule.weekday - first.getDay() + 7) % 7) + 7 * (rule.nth - 1))
}

/**
 * The next n observances from today (inclusive), wrapping into next year. A
 * rule day that has passed is re-derived for next year, so its date can differ
 * from this year's. Same-date days keep data order (Array#sort is stable).
 */
export function nextAwarenessDays(today: Date, n: number, days: AwarenessDay[] = defaultDays): UpcomingDay[] {
  const start = startOfDay(today)
  return days
    .map((day) => {
      let date = occurrence(day.when, start.getFullYear())
      if (date < start) date = occurrence(day.when, start.getFullYear() + 1)
      return { day, date, daysAway: daysBetween(start, date), activity: activityFor(day.activity) }
    })
    .sort((a, b) => a.daysAway - b.daysAway)
    .slice(0, n)
}
```

```ts
export function slugify(name: string): string {
  return name.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')
}

const yyyymmdd = (d: Date) =>
  `${d.getFullYear()}${String(d.getMonth() + 1).padStart(2, '0')}${String(d.getDate()).padStart(2, '0')}`

/** RFC 5545 TEXT escaping. */
function escapeText(s: string): string {
  return s.replace(/\\/g, '\\\\').replace(/;/g, '\\;').replace(/,/g, '\\,').replace(/\r?\n/g, '\\n')
}

/** RFC 5545 §3.1: lines over 75 octets continue after CRLF + space. The copy is ASCII, so characters are octets. */
function fold(line: string): string {
  const parts = [line.slice(0, 75)]
  for (let i = 75; i < line.length; i += 74) parts.push(` ${line.slice(i, i + 74)}`)
  return parts.join('\r\n')
}

/** A one-event .ics file for an observance, as an all-day event on its date. */
export function icsFor(u: UpcomingDay, now: Date = new Date()): string {
  const start = u.date
  const end = new Date(start.getFullYear(), start.getMonth(), start.getDate() + 1)
  const stamp = now.toISOString().replace(/[-:]/g, '').replace(/\.\d{3}/, '')
  return (
    [
      'BEGIN:VCALENDAR',
      'VERSION:2.0',
      'PRODID:-//EcoQuest Foundation//This Week for the Planet//EN',
      'CALSCALE:GREGORIAN',
      'BEGIN:VEVENT',
      `UID:${slugify(u.day.name)}-${yyyymmdd(start)}@ecoquestfoundation.org`,
      `DTSTAMP:${stamp}`,
      `DTSTART;VALUE=DATE:${yyyymmdd(start)}`,
      `DTEND;VALUE=DATE:${yyyymmdd(end)}`,
      `SUMMARY:${escapeText(u.day.name)}`,
      `DESCRIPTION:${escapeText(`${u.day.why}\n${u.day.url}`)}`,
      `URL:${u.day.url}`,
      'END:VEVENT',
      'END:VCALENDAR',
    ]
      .map(fold)
      .join('\r\n') + '\r\n'
  )
}
```

```js
// Weekly check that every official page the homepage's "This Week for the
// Planet" section links to still answers. Run by
// .github/workflows/weekly-rebuild.yml. Writes broken-links.md when anything
// fails (the workflow turns it into a GitHub issue) and always exits 0, so a
// moved page never blocks a rebuild.

import { readFile, writeFile } from 'node:fs/promises'
import { pathToFileURL } from 'node:url'

const SOURCES = ['src/data/awarenessDays.ts', 'src/data/seasons.ts']
const USER_AGENT = 'Mozilla/5.0 (compatible; EcoQuestLinkCheck/1.0; +https://www.ecoquestfoundation.org)'
const TIMEOUT_MS = 10_000

/** Every quoted http(s) URL in the text, once each, in order of appearance. */
export function extractUrls(text) {
  return [...new Set(text.match(/https?:\/\/[^'"`\s]+/g) ?? [])]
}

const ok = (status) => status >= 200 && status < 400

/** The final HTTP status for a URL, or 0 if nothing answered. HEAD, then GET; the pair is tried twice. */
export async function checkUrl(url, fetchFn = fetch) {
  let status = 0
  for (let attempt = 0; attempt < 2; attempt++) {
    for (const method of ['HEAD', 'GET']) {
      try {
        const res = await fetchFn(url, {
          method,
          redirect: 'follow',
          headers: { 'user-agent': USER_AGENT },
          signal: AbortSignal.timeout(TIMEOUT_MS),
        })
        status = res.status
      } catch {
        status = 0
      }
      if (ok(status)) return status
    }
  }
  return status
}

async function main() {
  const texts = await Promise.all(SOURCES.map((file) => readFile(file, 'utf8')))
  const urls = extractUrls(texts.join('\n'))
  const results = await Promise.all(urls.map(async (url) => ({ url, status: await checkUrl(url) })))
  const broken = results.filter((r) => !ok(r.status))
  console.log(`Checked ${urls.length} links, ${broken.length} broken.`)
  for (const b of broken) console.log(`  ${b.status || 'no response'}  ${b.url}`)
  if (broken.length === 0) return
  const list = broken.map((b) => `- ${b.url} — ${b.status || 'no response'}`).join('\n')
  await writeFile(
    'broken-links.md',
    `The weekly check could not reach these official pages linked from the homepage's This Week for the Planet section:\n\n${list}\n\n` +
      'Fix the URL in `src/data/awarenessDays.ts` or `src/data/seasons.ts`. Some sites refuse automated requests, so open each link in a browser first.\n',
  )
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) await main()
```

```yaml
# Keeps the homepage's "This Week for the Planet" section fresh with no manual
# work. The page recomputes from the visitor's date in the browser; this
# rebuild keeps the static HTML (what crawlers and link previews see) within
# a week of today. It also checks every official link and opens one issue if
# any break.
#
# One-time setup: create a Deploy Hook in Vercel (Project → Settings → Git →
# Deploy Hooks, branch main) and save its URL as the repository secret
# VERCEL_DEPLOY_HOOK_URL. Without it, the rebuild step is skipped.

name: Weekly rebuild and link check

on:
  schedule:
    - cron: '0 8 * * 1' # Mondays 08:00 UTC
  workflow_dispatch:

permissions:
  actions: write # re-enable this workflow, see the last step
  contents: read
  issues: write

jobs:
  weekly:
    runs-on: ubuntu-latest
    steps:
      - name: Rebuild the site
        env:
          HOOK: ${{ secrets.VERCEL_DEPLOY_HOOK_URL }}
        run: |
          if [ -z "$HOOK" ]; then
            echo "::notice::VERCEL_DEPLOY_HOOK_URL is not set; skipping the rebuild."
          else
            curl -fsS -X POST "$HOOK" > /dev/null
            echo "Rebuild requested."
          fi

      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 24

      - name: Check official links
        run: node scripts/check-planet-links.mjs

      - name: Open or update the broken-links issue
        if: hashFiles('broken-links.md') != ''
        env:
          GH_TOKEN: ${{ github.token }}
          TITLE: 'Planet calendar: broken links'
        run: |
          number=$(gh issue list --state open --search "in:title \"$TITLE\"" --json number,title \
            --jq ".[] | select(.title == \"$TITLE\") | .number" | head -n1)
          if [ -n "$number" ]; then
            gh issue comment "$number" --body-file broken-links.md
          else
            gh issue create --title "$TITLE" --body-file broken-links.md
          fi

      # GitHub turns off scheduled workflows in public repos after 60 days
      # without repository activity. Re-enabling resets that clock, so the
      # schedule keeps running even when nobody commits.
      - name: Keep the schedule alive
        env:
          GH_TOKEN: ${{ github.token }}
        run: gh api -X PUT "repos/${{ github.repository }}/actions/workflows/weekly-rebuild.yml/enable"
```
